## 現在すでにあるもの

4タブ（今・時刻表・運行情報・設定）、タブごとのStack、Push/Pop、指に1:1で追従する左端Swipe Back、App/Browser Backの同期、スクロール・入力・選択・地図位置の保存がある。

検索はNowまたは時刻表→検索→結果→経路詳細→案内準備。交通機関別の地点候補、英語・駅番号・別名、3経由と滞在、到着／料金／乗換順、カード全体tap、条件変更、次の出発検索、履歴・保存先の削除、検索条件の共有がある。取得済み番線と途中駅も表示できる。これらを新規実装扱いで重ねない。

烏丸線・近鉄京都線・直通・K/B境界、北3とその他全既存バス／停留所、次駅Hero、降車、前方／反対方向列車、Realtime、遅延分析、全駅時刻表、折返し、運行・接近、運賃／定期、地図、GPS、通知、Dark Mode、Dynamic Type、Reduce Motion、設定を保持する。

UI整理では、未乗車ホームの閉じた検索に残っていた透明な144pxを消し、ステータスの過大な固定高を整理した。タイトル＋矢印の行と、アイコン付きの行のgridを分けた。駅詳細・近く・折返し等の独立CTAは全幅・間隔12px。検索／時刻表／定期券／rangeの操作領域は44px以上。大きな文字で時刻が重ならない列、タブバーと接触しない経路詳細footer、候補を閉じるEscapeとBackの分離を実装した。

## 競合との重要な違い

1. Google MapsのiPhone公式ヘルプでは、経路詳細の出発駅の下に後発時刻を最大2件表示し、矢印→候補→「その他の出発情報」で便一覧を開く。便を選ぶと現在と後続交通機関の所要時間を更新する。
2. Yahoo!乗換案内の公式画面例では、候補に早・楽・安、結果の上部に一本前／一本後がある。詳細には発着、番線、途中駅、乗車位置などがある。詳細時刻周辺の矢印の正確なtap挙動は実機で追加確認すること。
3. MyMapの経路詳細の出発時刻は静的な `<time>`。時刻を押して同じ区間の別便を選ぶUIはない。
4. MyMapの「次の出発を探す」は最初の便を越える時刻から経路全体を再探索する。区間の便を直接選び、後続接続まで更新する機能とは違う。
5. 駅時刻表の便を押して便詳細を見る機能はあるが、表示中の経路のLegへ選んだ便を反映する連携はない。
6. MyMapの案内準備は主に選んだ乗車区間を扱う。複数Legを通した徒歩→乗車→乗換→次便→到着の状態と誘導は不足している。
7. 自宅／職場・住所／施設・乗車位置・入口／出口・混雑予報・車椅子対応・運休回避・網羅的な始発／終電は不足またはデータ整備が必要。
8. Googleの色は定刻／早着／遅延／実測未更新、MyMapのsource dotは実測／予測／予定。同じ色でも意味が異なる。MyMapの左端Swipe Backと、Googleの候補カード左右切替も別の操作。

## 次の改修で最優先に実装すること

**経路詳細からの区間便選択を完成させる。**

望ましい操作：
経路詳細の各乗車区間の「出発時刻」を44px以上のボタンにする
→ 同じ区間・交通機関・方向の便選択画面へPush
→ 発車・到着・種別・行先・取得済み番線・実測／予定を見て選ぶ
→ その区間以降の接続を再探索
→ 更新内容を確認して同じ経路詳細へ戻る。

便の候補はList Row、選択中にチェック。Back labelは経路詳細。未取得・0件・遅延・オフライン・古い情報・取得途中のキャンセルを扱う。長い便一覧を無条件にSheetへ入れない。短いFilter／SortはSheetでよい。時刻表への単なるリンク追加で完成扱いしない。

## 必要なモデルと責務

- 識別子は `serviceId + tripId + 運行日 + fromStopId + toStopId + direction + legIndex + routeRevision`。表示名・時刻・同じ行先だけで便を同定しない。
- 入力・表示・原本の経路snapshot・編集中の便・確定経路を分ける。元の経路を変えずにキャンセルできること。
- 選んだ便が乗車駅と降車駅の両方へ正しい順で停車すること。急行通過、直通K/B境界、北3の会社・休校日、方向違いを検証する。
- 選択後は後続の乗車・徒歩・滞在・乗換余裕・着時刻・定期控除後の追加運賃を再計算する。間に合わない接続をそのまま残さない。
- 日跨ぎは運行日と24:xxの交通時刻を保持して扱う。時刻だけを翌日の日付に付け替えない。
- 全区間の遅れに同じ値を足しただけで再計算した扱いにしない。公式データの欠測、未確定終着、予測を区別する。
- 便のない区間や未取得の番線を生成しない。京都バスODPTが未設定なら公式時刻表の案内として扱う。
- 時刻表示を変えただけで、実際の案内対象やonArmが元の便のままになる実装は禁止。

関係ファイル：
`public/js/route-search-ui.js`（Screenと共有snapshot）、`route-search-view.js`（候補・詳細）、`route-search-model.js`（入力・比較・次便・共有条件）、`planner-worker.js`／`search-core.js`／`router.js`（探索）、`journey-session.js`（案内対象）、`timetable-ui.js`（便データ）、`navigation.js`／`navigation-core.js`（Stack・保存）、`navigation-motion.js`（共通Motion）。

巨大なdocument-level click routerを増やさない。画面ごとのControllerで処理する。既存の探索・公式時刻表・Workerを使い、別のダミー経路実装を作らない。CSS末尾の大量上書きではなく、各要素の所有ファイルの既存ルールを整理する。

## UIの座標・配置基準

- 390×844、Light/Dark、100/150/200%。805pxと320pxも確認する。
- 操作領域は44px以上。別actionの間隔は8px以上、主要CTA groupは12px。連続するList Rowは区切り線でよい。
- 文字は省略が適切な箇所以外で切らない。時刻の数字列、アイコン、本文、矢印を別の列で整列。
- 閉じた領域は透明にするだけでなく、レイアウト上の高さ0、フォーカス不可にする。
- 大きな文字では自然に縦へ並べる。文字を小さくして無理に押し込めない。
- footerはsafe-areaとタブバーを避ける。キーボード表示中は浮遊しない。
- 内容がない空き面を、巨大なカードや架空の近く情報で埋めない。
- 入力候補を閉じる操作で画面まで戻さない。縦scroll、地図Pan、Sheet drag、左端Backを混同しない。

## 必須検証と成果物

`npm run check`、`npm test`、`npm run build`、`npm run test:browser`、`npm run test:pwa`。
`BROWSER_UI_AUDIT=1 npm run test:browser` は画面の座標・間隔・ヒット領域の拡張検証。環境はNode22、Playwright。クラウドの環境スクリプトがあれば使用する。

追加する実用テスト：
- 経路詳細→便選択→別便→後続接続／料金更新→案内開始。実際に選んだtripIdが案内対象であること。
- 同名駅の異なる会社、方向違い、急行通過、直通、バス、北3、運行日の違い・休校日・24:xx。
- 便が取れない、終着時刻未確定、遅延で接続不可、タイムアウト、0件、オフライン、古いsnapshot、選択中の再取得。
- 戻る／Swipe／Browser Back、キャンセル、タブを往復、再読込後の入力・選択・スクロール保持。
- 文字200%でも押せること。VoiceOver、iPhone実機のキーボードとOS Edge Backは別途実測する。

完了時は画面別のBefore/Afterと座標JSON、変更した操作、選便データと再計算の根拠、通ったテスト、公開版、残る未実装を報告する。競合の公式画面から分かることと、実機で未確認のことを分ける。
