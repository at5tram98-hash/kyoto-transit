# ATS（Auto transportation system）Beta 設計

利用者の操作をできるだけ減らし、状況に合わせて「今」画面を案内する仕組みです。段階的に開発しているため、ATSを表示する場所には必ず「Beta」を付けます。

## 1. 情報の集め方（`public/js/ats-sensors.js`）

ATSは、判定に使う情報をすべてセンサー集約でまとめて読みます。アプリ状態を直接は参照しません。各情報には「どこまで信頼できるか」を付けます。センサーの値がないときは「不明」として扱い、「静止」とは見なしません。

| 情報 | 内容 | 品質 |
|---|---|---|
| 位置 | GPSの測位 | precise（誤差50m以下）／coarse／stale（45秒以上更新なし）／missing／loading／denied |
| 速度 | 端末が出すGPS速度。ない場合は直近の軌跡の中央値 | 出どころ（gps／track）。不明ならnull |
| 動き | 加速度センサー：静止／歩行（歩調）／乗り物（速度を伴う連続振動）／動きあり／不明 | 許可状態（許可済み／未許可／拒否） |
| 通信 | オンラインかどうか、公式接近情報がどれだけ新しいか | 経過時間 |
| 文脈 | 運行日区分・時刻・自宅（端末内のみ）・付近の停留所と駅 | 位置が使えるときだけ |
| 乗車 | 乗車中の便、検知セッションの段階、候補の数 | — |

純粋関数 `fuseSnapshot()` で入力からスナップショットを作り、テストでもそのまま使います。

## 2. 場面の判定（`public/js/ats-scene.js`）

`classifyScene(snapshot)` で次の場面を判定し、判定の根拠も返します。

- 乗車中（バス／電車）
- 再確認中
- 自宅
- バス停にいる
- 駅にいる
- 乗り物で移動中
- 徒歩
- 付近
- 不明

地下ではGPSがなくても、加速度センサーが乗り物の振動を示していれば「乗り物で移動中」と判定します。

`assessScene(snapshot, memory)` は判定をなめらかにする役割です。新しい場面は10秒続くか、確信度が0.8以上になるまで画面に反映しません。そのため、GPSが一瞬ずれただけで表示がちらつくことはありません。乗車の開始・終了と再確認は即座に反映します。バス停・駅・自宅では滞在時間も数えます。

## 3. 段階（`public/js/ats.js`）

| LV | 名称 | 動作 |
|---|---|---|
| 0 | オフ | 状況を判定しない |
| 1 | 状況の表示 | 状況を表示する（操作の提案は手動で使う） |
| 2 | 提案 | 乗車候補を提案する。乗車はタップで確定 |
| 3 | 自動乗車 | 位置・動き・時刻表・接近情報が一致したら自動で乗車案内を始める |
| 4 | 自動画面切替 | バス停では接近情報、自宅ではよく使う経路を自動で表示する |
| 5 | 完全自動（実験的） | 下記のパイロット |

動作モードによって使える段階の上限が決まります。上限はオートがLV.5、マニュアルがLV.2、省電力がLV.1です。

## 4. LV.5 パイロット（`public/js/ats-pilot.js`）

LV.3とLV.4ですでに使っている根拠だけを使い、次の操作を自動で行います。

- **降車予測**：降車停留所が未設定のまま乗車したとき、この先の停留所から降車停留所を予測して設定します。予測には端末内の検索履歴を優先して使います。乗車停留所から始まる検索を最優先にし、次にほかの検索、最後に保存した場所の順です。予測したことは通知し、利用者が変更できます。
- **確認なしの乗車**：次の条件をすべて満たしたときだけ、確認のタップなしで乗車を開始します。
  - 乗り物で移動中の状態が30秒続いている
  - 候補がちょうど1便に絞られている
  - スコアが55以上である
  - 進行方向が否定されていない
- 各操作は1回だけ行います。同じ便には繰り返しません。

純粋関数 `pilotSteps()` が「何をするか」を決め、`runPilot()`（`ats-ui.js`）が5秒ごとに実行して通知します。

## 5. 画面

- **「今」のステータス**：iPhoneのステータスバーのように、アイコンを1行に並べます。並びは時計、運行日、現在地、ATSの段階、モーションセンサー、接近情報の鮮度（電波マーク）、動作モードです。その下に状況を1行で表示し、場面に合った操作を最大3つ置きます。タップするとATSシートを開きます。
- **ATSシート**：センサーと判定の内訳、動作モード、段階、自宅の設定、プライバシーの説明をまとめています。
- **Quick**：ナビゲーションバーに統合しました。タップで一覧を開きます。長押ししてそのまま指を動かすと、その場で選べます。

## 乗車便の時刻特定（ride-timing.js）

市バスの乗車は停留所の通過順で系統・向き・乗車停留所までは分かるが、どの便かは分からない。
乗車が確定したら（自動検知・チェックイン・保存から復元のいずれも）、その日の公式時刻表
（市バス・京都バスは静的フィード、北3は全停留所時刻表、地下鉄・近鉄は各フィード）から
乗車停留所の発車が検知時刻に最も近い便（[−25分, +6分]、先に出た便を優先）を選び、
各停留所の時刻を入れる。区間所要時間から補完された時刻は「推定」と表示する。
該当便がないときだけ「停留所の順に案内中」とし、1分ごとに再照会する。時刻を作り出すことはしない。

## アニメーション（ats-motion.js）

- 場面が変わると、アイコンがばね（UIKit 既定のわずかなオーバーシュート）で現れ、説明文はぼかしから浮き上がる。
- アイコンの周りのリングは判定の確からしさまで時計回りに満ちる。乗車確定でリングが満ち、波紋が一度広がる。
- 判定中（移動・候補・再確認）は AirDrop のような波紋が繰り返し広がる。
- 場面の切り替え待ち（10秒の保持）は、カード下端の細線が満ちて示す。
- 状態の変わったステータスアイコンは一度弾み、電波バーは順に点く。
- `prefers-reduced-motion` ではすべて止める。

## マイク（車内放送）の使用条件（mic-policy.js）

- マイク（音声認識）を使うのは **GPS精度が低いとき（精度50m超）だけ**。京都ではほぼ地下（烏丸線・近鉄直通区間）。
  地下鉄駅で位置を確認した直後（15分以内）にGPSが消えた場合も地下とみなす。
- 精度が良いとき・位置情報がないとき・自宅付近では使わない。音声認識の開始と継続はすべて `micAllowed()` を通る。
- 条件を満たすと即座に聞き始める（間隔2秒で再開）。ブラウザーがタップなしの開始を拒んだときは、
  今画面に「車内放送を聞く」ボタンを出す。使用中はステータス行にオレンジのマイクを表示する。

## 車内放送による地下鉄・近鉄の検知

- 放送の文型：次駅「次は四条、四条です」「この電車は国際会館行きです」「地下鉄線を通り国際会館行き」、
  到着「竹田、竹田です」、英語「The next stop is Shijo, station number K09」「This is Takeda」。
- 聞こえた駅の前後の駅を出た列車のうち、その駅をまだ通っていない列車だけを候補にする。
- 同じ列車で2駅を順に聞いたら（または1駅＋加速度センサーで走行中）、GPSなしでも乗車を確定する（LV.3以上）。
- 精度の低い位置では駅を名指せないため、最後に確認した駅と放送を使う。精度の低い位置からは進行方向を推定しない。

## 到着ポップアップ（arrival-sheet.js）

- 目的地に着くと「〇〇に到着しました」を表示し、徒歩圏（600m）の地下鉄・近鉄駅から、歩いて間に合う
  40分以内の発車を行先ごとに2本まで出す。選ぶと次の乗車として設定され、ATSが乗車を見守る。
- 行き先を決めて検索（ここを出発地にした経路検索）もできる。
- 自宅付近（400m以内）に着いたときは「自宅に到着しました」だけを表示し、乗り継ぎは出さない。
