# MyMap 画面別 UI・操作比較と座標監査

今回の対象は「UI整理」と「次回の改修に渡す差分の明確化」。比較の基準は今回開始時の main `d55c03b`（公開アプリ `0c1a8378b3b6`）。従来の4タブ、交通案内中心のホーム、iOSの配色、Navigation Stack、既存機能を維持し、地図をホームの主役にしない。

## 1. 証拠と比較の限界

MyMapは実ブラウザーで、画面遷移・クリック・スクロール・入力を行い、`getBoundingClientRect()` でCSSピクセルの座標を測定した。390×844 と805×844、Light/Dark、390pxでは100/150/200%の文字サイズ。変更前は34画面×8状態＝272画像・座標記録。時刻表とGPSは決定的な検証用データであり、運行精度の実測ではない。

競合は今回あらためて取得した公式紹介画面・iPhone向けヘルプを根拠にする。競合の実機をこの環境で操作したとは主張しない。競合の実機座標、タップ領域、モーション時間は未測定。公式の300px切り抜き画像を390pxの実機スクリーンショットと扱わない。確認できた操作と、未確認の点を分ける。

## 2. 実測で確認したUI不具合と整理

代表値は390×844、Light、100%。すべて左上を原点とするCSS px。色や機能を削って整えたものではない。

|対象|変更前の実測・原因|今回の整理|

### 接近情報の色の意味を取り違えない

G1の緑／橙／赤／黒は定刻・早着・遅延・実測未更新の意味。MyMapの source dot の緑／橙／灰は実測・予測・予定の出典を表す。同じ色でも意味が違う。「色が似たので同等」にはしない。改善するなら出典と運行状態を別のラベルで示す。GPSだけの推定を公式実測として緑にしない。

### 戻るとカード切替も別の操作

Googleの候補カードの左右スワイプ[G1]は候補や交通機関の切替。MyMapの左端Swipe Backは画面階層を戻る操作。MyMapにSwipe Backがあることは、候補カードの左右切替を実装した証拠ではない。追加時は左端24pxのBackと中央の候補操作を分離し、縦スクロールを壊さない。

## 5. 次回の優先順位と実測

1. **P1 区間の便選択**：時刻ボタン→同じ区間・方向の便→経路全体の再計算→確認→同じ経路詳細へ。詳細はPush、短い並べ替え・絞り込みはSheet。
2. **P1 経路全体の移動状態**：現在の案内準備は主に選んだ乗車区間を保持する。複数Legの乗換・徒歩・次の便まで通して案内する状態設計が必要。
3. **P1 保存先の再利用**：自宅／職場、交通機関を区別した保存先ラベル、固定路線、最近の入力、前便の再検索。
4. **P2 接続と乗換情報**：入口・出口・ホーム・乗車位置・歩行時間。存在しない公式データを推測で埋めない。
5. **P2 データ拡張**：施設／住所、運休回避、日跨ぎの始発／終電、車椅子・混雑。UIを置くだけで完成にしない。

競合実機との比較は、同じ駅・日付・時間・回線で入力→結果→詳細→他便→案内開始を各5回。操作数、入力誤選択、発車変更後の接続整合、戻り位置を計測。MyMapはiPhone Safariとホーム画面PWA、VoiceOver、キーボード、OSのEdge Back、Reduce Motion、100/150/200%、弱い回線／オフラインを確認する。別途、実到着との誤差、乗換歩行時間、実測欠測率、北3の運行会社・休校日、K/B境界を現地と公式資料で確認する。
