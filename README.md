# My Map — 京都の乗換案内

京都の限られた駅・停留所を選び、Yahoo!乗換案内に検索条件を渡す、日本語のモバイル対応Webアプリです。主検索のために時刻表をアプリへ収録する必要はありません。

**公式画面取得と日本語OCRを実装。Yahoo!の検索結果をアプリ内に自動で読み戻す機能は未接続です。**

公開アプリ：[My Map](https://at5tram98-hash.github.io/kyoto-transit/)

ソース：[at5tram98-hash/kyoto-transit](https://github.com/at5tram98-hash/kyoto-transit)

## 実装済み

- 駅・停留所名、別名、バス系統番号で場所を選択。
- 出発・到着・最大3つの経由地・出発日時を入力し、Yahoo!の検索結果画面を別タブで開くURLを生成。
- バス停名は会社名付きで渡し、同名の施設との混同を防ぐ。空路・新幹線・有料特急・高速バス・フェリーを除外し、路線バスを含めて検索。
- 各経由地で0〜180分の滞在・折り返し待ちを設定。
- 前区間の実際の到着日時を入力すると、滞在時間を加えた日時で次区間をYahoo!検索。日付をまたぐ場合にも対応。
- 場所のお気に入り・検索条件の保存、設定のバックアップと復元。
- 市バスフリー、京都バスの対象区間、地下鉄の国際会館〜京都の定期を初期設定。期限と区間を変更可能。
- 地下鉄・近鉄・直通・京都バス・共通系統を持つ市バス停間では、特定の移動方法の通常運賃と追加支払額の目安を併記。Yahoo!の検索結果から計算した運賃ではありません。
- ポケロケ plus+で停留所の対象系統・行先・のりばを取得し、選択した接近画面を自動取得。
- 近鉄の公式運行画面を自動取得。
- Tesseract.js 7の日本語・英語OCRで取得画像の文字を実際に認識。表の文字を位置から同じ行にまとめて表示。
- 原画像・OCR原文・認識信頼度・取得時刻を端末に保存。2分を過ぎた画像は保存情報として表示。
- 手元の画像も上下で切り取り、端末内のOCRで認識・保存。
- My Moneyの元CSSを参照した色・字体・カード・浮かぶ下部ナビゲーション。ライト／ダーク表示。既存の保存設定を継承。

## 対応範囲

| 交通機関 | 登録範囲 |
| --- | --- |
| 地下鉄 | 烏丸線 国際会館〜竹田の全15駅 |
| 近鉄 | 京都〜近鉄奈良、竹田〜近鉄奈良、地下鉄との直通 |
| 京都バス | 国際会館駅前・京都産業大学前の2地点 |
| 京都市バス | 202（八条口を含む）・204・205・206・10・208・78・13・43の公式停留所一覧 |
| 96系統 | 現行の公式系統一覧で確認できず未登録。運行している情報を確認できた時点で追加 |

Yahoo!側では対象外の路線を提案することがあります。このアプリから交通事業者や個別の系統を厳密に制限することはできません。経由地は同名の`via`パラメーターを順に追加して送信します。実ブラウザで、丸太町→国際会館の結果表示と、近鉄丹波橋・高の原の2地点がYahoo!の検索条件に入ることを確認しました。経由地を通過する検索であり、各地点での下車・滞在は区間検索で確認してください。

## 定期券と運賃

| 初期設定 | 定期適用後 |
| --- | --- |
| 対象の市バス | 追加0円／普通運賃230円の目安 |
| 京都バス 国際会館駅前〜京都産業大学前 | 追加0円／普通運賃230円の目安 |
| 地下鉄 京都〜国際会館 | 追加0円／京都〜国際会館の普通運賃290円の目安 |
| 地下鉄 京都以南 | 定期区間を超える部分を別計算 |
| 近鉄 | 普通運賃の目安を追加支払額として表示 |

京都バスの0円設定は、利用者が対象区間でも定期が使えると申告したことに基づきます。Yahoo!側の運賃にはこのアプリの定期設定は反映されません。バスの乗継割引、地下鉄・近鉄の連絡運賃の割引、折り返し乗車・途中下車の乗車券条件は未反映です。精算時は事業者の案内を優先してください。

## 折り返しの使い方

1. 出発「丸太町」、到着「国際会館」を選ぶ。
2. 経由1「近鉄丹波橋」、経由2「高の原」をこの順で追加。
3. 高の原の滞在を10分などに設定し、必要に応じて「改札を出る」を選ぶ。
4. 全体検索では経由地をYahoo!へ渡す。滞在時間はYahoo!の全体検索に反映されない。
5. 区間検索で前区間の実際の到着日時を入力し、滞在後の日時で次区間を検索する。

普通のみ・急行のみ、乗換余裕、徒歩上限は、下記の試作比較用の条件です。Yahoo!への厳密な指定は未対応です。

## 試作のルート比較

主検索の下にある折りたたみから利用できます。人工の発車間隔・所要時間・バスの経路順を使い、折り返しや複数経由地のUIと計算を検証します。**日常の乗車判断には使用しないでください。**

経由地の通過だけでは条件を満たさず、必ず下車して指定時間待ちます。同じ駅や路線を逆方向へたどることも許可します。「早い」「乗換が少ない」「待ちが少ない」「歩きが少ない」を重み付けで比較します。探索は10時間・9回の乗車まで、各地点・経由段階で最大6ラベルを保持する近似探索です。全候補の厳密な最適性を保証しません。

実番線は登録していません。画面では「未取得」と明示します。停留所名の一覧から実際の運行順は推定できないため、試作のバス経路を実経路として使うこともできません。

## 起動・検証

Node.js 22以降を利用します。OCRにTesseract.js 7、サーバー開発にWrangler 4を利用します。

```sh
npm ci --ignore-scripts
npm run check
npm test
npm run build
python3 -m http.server 8080 --directory dist
```

`http://localhost:8080` を開いてください。HTMLを直接開く `file://` ではモジュールとJSON読込が動作しません。37件の自動テスト、JavaScript構文、HTML ID・静的参照、ビルドを検証しました。GitHub Pagesの公開、公開画面からのYahoo!検索、丸太町→国際会館の通常260円・定期適用後0円、京都バスの通常230円・定期適用後0円をクラウドブラウザで確認しました。公開版でポケロケの204系統・Bのりばの画面取得と日本語OCR、近鉄の京都線・奈良線のOCR表示も確認しました。スマートフォン実機での検証は未実施です。

## GitHub Pages公開

`.github/workflows/pages.yml` を同梱しています。

1. 新しいGitHubリポジトリ `kyoto-transit` を作成する。
2. このフォルダの内容を `main` ブランチへ登録する。
3. Settings → Pages → Build and deployment の Sourceを **GitHub Actions** にする。
4. Actionsで「検証とGitHub Pages公開」を実行し、成功後の公開URLを確認する。

GitHub FreeではパブリックリポジトリのPages公開が利用できます。プライベートリポジトリでのPages利用は契約プランを確認してください。パスは相対指定なので `/kyoto-transit/` 配下の公開に対応します。ユーザーの設定・画像は端末内に保存され、公開するソースには含まれません。

## 公式画面の取得とOCR

`worker/index.js` は Cloudflare Browser Run のブラウザーbindingを使用し、公式ページの画像を取得します。`worker/wrangler.jsonc` に設定と対象停留所を収録。公開した取得サーバーは `public/js/live.js` から接続します。

- バス：公式停留所選択ページから対象の系統・方向・のりばを読み、選択した同じ条件を接近画面へ渡して撮影。
- 近鉄：`https://www.kintetsu.jp/unkou/unkou.html` の運行画面を撮影。
- OCR：アプリと同じ配信元にTesseract本体、Worker、WASMを配置。初回は日本語・英語のモデルを取得し、認識自体は端末内で処理。
- 更新ボタンを押したときだけ取得。常時ポーリングはしません。サーバーは1分に8リクエスト／IPに制限。対応停留所以外や任意URLの取得は受け付けません。
- 原画像と文字は端末内へ保存し、公開リポジトリへ収録しません。個人の閲覧用です。
- 取得日時が不明、未来、2分以上前の場合は最新情報として扱いません。OCRで読み取れない情報から正常運行を推測しません。

Cloudflareの無料プランではブラウザー稼働時間が1日10分に制限されます。上限や公式サイト側の障害・変更時は画面にエラーを表示し、公式サイトで確認できるリンクを残します。自動で有料プランへ変更はしません。

サーバーを再配置する場合：

```sh
npx wrangler types --config worker/wrangler.jsonc worker/worker-configuration.d.ts
npx wrangler deploy --dry-run --config worker/wrangler.jsonc
npx wrangler deploy --config worker/wrangler.jsonc
```

Yahoo!へ検索条件を渡す方式は継続しています。Yahoo!の検索結果の自動取得・再表示、番線と到着時刻の正規化は未実装です。

## 任意の時刻JSON

主検索には不要です。「定期・設定」の読込は試作比較用の開発機能です。`schemaVersion: 1`、`source`、`validDates`、`stops`、`services`、任意の`walks`を持つJSONを受け付けます。公式フィードやYahoo!のデータを自動収集・変換するツールは同梱していません。

各`stops`は`id`と`name`を持ち、`services`は`id`・`label`・`operator`（`subway`/`kintetsu`/`through`/`citybus`/`kyotobus`）・`category`（`local`/`express`）・停車順の`stops`・`trips`を持ちます。各便は`id`・`date`・停車駅と同じ長さの`arrivals`/`departures`配列を持ち、時刻は営業日0時からの分数です。翌日1時は1500分です。有効日の実便がない区間は人工の便へ補完しません。読込データの正確性・使用許諾は別途確認が必要です。
